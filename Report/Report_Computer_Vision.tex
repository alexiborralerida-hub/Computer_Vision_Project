\section{Introduction}

This document shows the procedure followed to accomplish the project, its different main steps and difficulties that have arisen as well as their proposed solution.

\section{Problem description}

In this section the description of the problem is taken from the project proposal document:\\

Object detection techniques based on computer vision can be deployed in super market scenarios for the creation of a system capable of recognizing products on store shelves.\\

Given the image of a store shelf, such a system should be able identify the different products present therein and may be deployed, e.g. to help visually impaired costumers or to automate some common store management tasks (e.g. detect low in stock or misplaced products).

\section{Task definition}

The definition of the task is provided by the project proposal document:\\

Develop a computer vision system that, given a reference image for each product, is able to identify boxes of cereals of different brands from one picture of a store shelf. For each type of product displayed in the shelf the system should report:

\begin{enumerate}
	\item Number of instances.
	\item Dimension of each instance (width and height of the bounding box that enclose them in pixel).
	\item Position in the image reference system of each instance (center of the bounding box that enclose them in pixel).
\end{enumerate}

The task is also defined in three sub-tasks that increment the difficulty in each step:

\begin{itemize}
	\item \underline{Step A - Multiple Product Detection:} Develop an object detection system to identify single instance of products given: one reference image for
each item and a scene image. The system should be able to correctly identify all the product in the shelves
image. One way to solve this task could be the use of local invariant feature as explained in lab session 5.
	\item \underline{Step B - Multiple Instance Detection:} In addition to what achieved at step A, the system should now be able to detect multiple instance of the
same product. Purposely, students may deploy local invariant feature together with the GHT (Generalized
Hough Transform). More precisely, rather than relying on the usual R-Table, the object model acquired at
training time should now consist in vectors joining all the features extracted in the model image to their
barycenter; then, at run time all the image features matched with respect to the model would cast votes
for the position of the barycenter by scaling appropriately the associated joining vectors (i.e. by the ratio of
sizes between the matching features). 
	\item \underline{Step C (optional) - Whole shelve challenge:} Try to detect as much products as possible in this challenging scenario: more than 40 different product
instances for each picture, distractor elements (e.g. price tags…) and low resolution image. You can use
whatever technique to achieve the maximum number of correct detection without mistake.

\end{itemize}
\section{Solution development}
The project solution process will be explained along this section. 

\subsection{Step A - Multiple Product Detection:}
\label{StepA}

\subsubsection{Laboratory Session 5 procedure}
Following the description from the task, the procedure from Laboratory Session 5 is used.\\

It uses SIFT (Scale-Invariant Feature Transform) detector to find the keypoints for both scene and model images, and SIFT descriptor to generate the descriptors of those keypoints. To match the features FLANN (Fast Library for Approximate Nearest Neighbors) is used as it is an approximation of an exact search approach. After that, Lowe's distance ratio test filters the matches to reject wrong ones. Finally, RANSAC (Random Sample Consensus) is used to obtain a robust homography that translates keypoints from model image to scene image.\\

This scheme is modified to cycle through each scene image, and for each scene image to cycle through each model image to obtain the detections. Moreover, the original method is modified to obtain a rectangular bounding box rather than a parallelepiped. These rectangles obtain the furthermost points in each direction from the matches, as seen here:

\begin{figure}[H]
        \centering
        \includegraphics[scale=0.7]{boundingbox.png}
        \caption{Bounding box example}
\end{figure}

This approach is done to make width and height pixel count output better seen in the images.

\subsubsection{Naive approach}

By following Laboratory Session 5 procedure without any addition, the results are not satisfactory. To understand this, it is necessary to know that SIFT works with grey scale images and finds features regardless of colour. As there are similar boxes that only change colour in some regions, these get confused by the algorithm\\

In this approach there is one degree of freedom: the minimum Lowe filtered matches necessary to consider a feature detection. Setting this threshold higher or lower does not reach a good solution, as similar shaped cereal boxes get misinterpreted easily without the notion of colour.\\

\subsubsection{Colour descriptors approach}

To consider colour into the feature match process, the decision is to enrich the descriptors with colour information. A local $2 \times 2$ crop is performed around each keypoint to extract colour information from an HSV color space image. From it, an $8 \times 8$ 2D color histogram is built, and then concatenated into the final descriptor. In the end, descriptors grow from 128 to 192.\\

However, results were not satisfactory, obtaining the same erroneous detections as before.\\

This has some possible explanations:\\

Standard SIFT values range from 0 to 255, while the histogram is normalized from 0 to 1. As well, the SIFT features are 128, and colour ones 64, so their influence is small. In addition, SIFT keypoints are placed around edges and text, neglecting box colour in the majority of times. Finally, orientation and scale invariance are lost in that portion of the descriptor, as the crop is fixed without accounting for rotation, scale or perspective distortion.

\subsubsection{Mahalanobis distance}

Mahalanobis distance was chosen over other methods such as RMS distance due to its advantages.

$$D_M = \sqrt{(x - \mu)^T \Sigma^{-1} (x - \mu)}$$

where $\mu$ is the mean BGR vector and $\Sigma$ is the $3 \times 3$ covariance matrix of the model's pixel distribution.

In natural images, $B, G,$ and $R$ channels are strongly correlated (changes in overall lighting shift $B, G,$ and $R$ together along a diagonal axis). Mahalanobis uses $\Sigma^{-1}$ to de-correlate the channels, tolerating natural luminance shifts while penalizing true chromatic discrepancies.\\

Moreover, if a cereal box naturally has high variance in one channel (e.g., lots of mixed red/orange tones on Orange Krave), a difference of 15 units in the red channel is normal and expected.
If another channel has low variance (e.g., almost zero blue content), even a small 5-unit increase in blue indicates the box is completely wrong (likely Blue Krave).
RMS is blind to this difference—it treats a 10-unit error identically across all channels. Mahalanobis divides each deviation by the model's observed standard deviation along that axis.\\

In this approach, instead of adding colour information to every descriptor, the colour is checked only for successful homographies, and both checks (geometry and colour) are decoupled.\\

In the beginning, a single threshold was applied for all cases of cereal box. However, different cereal boxes have different colour distributions: while ones have a uniform hue and generates small distances, others have white backgrounds with shapes and labels that generate bigger distances. Considering as well that some boxes have the same colours but for a change in background colour, it worked better to have a custom threshold for each cereal box case. For instance, if set loose enough (1.0) to avoid False Negatives for multi-colored boxes (Fitness, Jordans), it caused False Positives on look-alike variants (Nesquik Pink vs. Yellow Nesquik). If tightened to 0.3 to separate look-alikes, it caused False Negatives on almost everything else.

A later improvement included solving an issue related to the decoupling of geometry and colour checks. As SIFT does not include colour information, similar shaped graphics with a different background could be misinterpreted by SIFT as it selects the candidate with the highest amount of matches. That candidate will later be rejected by Mahalanobis threshold, and the output is that no matching is performed as SIFT will not check for the next. To correct that behaviour, for each box a maximum of 3 retries is performed, in which the pixels of an unsuccessful candidate are temporally removed to allow SIFT look for the next geometry.
